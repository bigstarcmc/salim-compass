# 살림나침반 — 모바일 전용 화면

Apps Script 웹앱은 그대로 "정밀 입력/관리용"으로 두고, 이 폴더는 **폰에서 앱처럼 보이는 가벼운 화면**입니다.
데이터는 전부 기존 Apps Script를 그대로 API로 불러와서 쓰기 때문에, 시트나 로직을 새로 만들 필요가 없어요.

## 구조

```
index.html   ← 이 파일 하나가 전부(HTML+CSS+JS). 빌드 과정 없음.
```

## 1. Apps Script 쪽 — API 키 확인

`common/Config.gs`에 이미 넣어드렸어요:
```
API_KEY: 'salim-compass-2026-jh'
```
바꾸고 싶으면 여기서 바꾸고 `clasp push -f` 하시면 됩니다. (URL에 그대로 노출되는 값이라, 남이 짐작하기 어려운 값으로 해두는 게 좋아요.)

## 2. 웹앱 URL 확인

Apps Script 편집기 → 오른쪽 위 **배포 → 배포 관리** → 웹앱 URL 복사
(`https://script.google.com/macros/s/AKfycb.../exec` 형태)

기존에 쓰던 테스트배포 URL 그대로 쓰시면 됩니다. 주소 하나로 화면용(HTML)과 데이터용(JSON API) 둘 다 처리하도록 만들어놨어요.

## 3. GitHub Pages로 올리기

기존 `poscohouse` 저장소는 이름 그대로 두고, **이 모바일 화면은 새 저장소로 따로 만드는 걸 추천해요** — 이름부터 "살림나침반"에 맞게 깔끔해지고, 나중에 주소도 헷갈리지 않아요.

1. GitHub에서 새 저장소 생성 (예: `bigstarcmc/salim-compass`, Public)
2. 그 저장소에 이 폴더 안의 **5개 파일을 전부** 올립니다: `index.html`, `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`, `icon-180.png` (전부 저장소 최상단에, 폴더 안에 넣지 말 것)
3. 저장소 Settings → Pages → Source를 `main` 브랜치, `/ (root)`로 설정.
4. 몇 분 뒤 `https://bigstarcmc.github.io/salim-compass/` 로 접속하면 화면이 뜹니다.

## 4. 진짜 앱처럼 설치하기

이제 "홈화면에 추가"가 아니라 **진짜 앱 설치**가 가능해요(PWA):

- **안드로이드(크롬)**: 주소 열면 자동으로 하단에 "앱 설치" 배너가 뜨거나, 오른쪽 위 점 3개 메뉴 → "앱 설치". 설치하면 다른 앱들처럼 앱 서랍에 아이콘이 생기고, 브라우저 주소창 없이 전체화면으로 실행돼요.
- **아이폰(사파리)**: 공유 버튼 → "홈 화면에 추가". iOS는 정책상 이 방식만 지원돼요.

`sw.js`(서비스워커)는 설치 가능하게 해주는 역할만 하고 **아무것도 캐싱하지 않도록** 일부러 비워뒀어요 — 예전에 겪으신 "코드 고쳐도 반영 안 되는" 문제가 여기서는 재발하지 않습니다.

## 5. Apps Script 배포 설정 확인 (중요)

접속이 "Failed to fetch"로 안 된다면 대부분 이 설정 때문이에요:
Apps Script 편집기 → 배포 → 배포 관리 → 쓰고 계신 배포 편집 → **액세스 권한을 "누구든지(Anyone)"로** 설정해야 폰에서도 로그인 없이 접속됩니다.

## 4. 최초 연결

처음 열면 "웹앱 URL"과 "API 키" 입력창이 떠요. 2번, 1번에서 확인한 값을 넣고 "연결하기" 누르면 끝 — 그다음부터는 폰에 저장돼서 다시 안 물어봐요.

## 지금 되는 것 / 안 되는 것

**됨**: 홈 대시보드, 캘린더(조회+4개조 전체보기+실시간 예상월급+일정/작업일지/일기 빠른등록), 급여예측(진한/선영 토글 전환+확정), 가계부 지출·변동소득 빠른입력. 누구로 볼지는 상단 배지 눌러 버튼으로 전환.

**PC 웹앱에서만**: 계좌/카드/카테고리/휴가코드 관리, 급여 항목 세부 수정(요율·공제 등), 고정지출 관리, 저축목표 만들기. — 이런 "설정성" 작업은 원래 웹앱 화면이 더 편해서 일부러 안 옮겼어요. 가끔 하는 일이라 폰 화면을 복잡하게 만들 필요가 없다고 판단했습니다.
